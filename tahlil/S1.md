# S1 — Webhook himoyasiz — istalgan odam super_admin bo'la oladi

> Eng kritik ochiq band. Bot Telegram'dan kelgan so'rovni haqiqiyligini
> tekshirmaydi — manzilni bilgan har kim soxta "update" yuborib, o'zini
> super-admin qilib ko'rsatib, botni to'liq egallab oladi.

## A. Dalil

**1) Webhook har qanday POST'ni qabul qiladi** — `passenger_wsgi.py:42-56`:

```python
def application(environ, start_response):
    path   = environ.get("PATH_INFO", "/")
    method = environ.get("REQUEST_METHOD", "GET")

    if path == "/webhook" and method == "POST":
        try:
            length = int(environ.get("CONTENT_LENGTH") or 0)
            body   = environ["wsgi.input"].read(length)
            update = Update.model_validate(json.loads(body))
            loop.run_until_complete(dp.feed_update(bot, update))
        except Exception as e:
            print(f"[WEBHOOK ERROR] {e}", file=sys.stderr)
        start_response("200 OK", [("Content-Type", "text/plain")])
        return [b"ok"]
```

So'rov manbai umuman tekshirilmaydi. `environ` dan `X-Telegram-Bot-Api-
Secret-Token` (WSGI'da `HTTP_X_TELEGRAM_BOT_API_SECRET_TOKEN`) o'qilmaydi.
JSON to'g'ri formatda bo'lsa — `dp.feed_update` ishga tushadi, tamom.

**2) `set_webhook` secret o'rnatmaydi** — `set_webhook.py:18`:

```python

```

`secret_token` argumenti berilmagan. Ya'ni Telegram ham har so'rovda maxfiy
sarlavha yubormaydi — himoya zanjirining ikkala uchi ham ochiq. (Grep:
`secret_token` — butun loyihada 0 natija.)

**3) Rol faqat `from_user.id` ga tayanadi** — `app/handlers/admin.py:33-41`:

```python
async def get_role(user_id: int) -> str | None:
    if user_id == SUPER_ADMIN_ID:
        return "super_admin"
```

Rol butunlay update ichidagi `from_user.id` ga bog'liq. Bu **oddiy sharoitda
to'g'ri** — chunki Telegram yuboradigan `from_user.id` ishonchli. Lekin (1)+(2)
tufayli update Telegram'dan kelganligi tasdiqlanmaganidan, hujumchi bu maydonni
xohlagancha qalbakilashtira oladi.

**4) `.env` da webhook siri yo'q** — `app/config.py:1-31` va serverdagi `.env`
kalitlari ro'yxati (SSH orqali tekshirildi): `WEBHOOK_SECRET` degan kalit yo'q.
Ya'ni siyosat ham, sozlama ham mavjud emas.

**5) Kirish nuqtasi ochiq va aniq:** webhook manzili — `https://bot.
bulutliiqtisodiyot.uz/webhook` (bugun o'rnatildi). Manzil formati standart
(`/webhook`), domen ochiq — topish qiyin emas.

## G. Yechim variantlari

**A) YUZAKI — webhook URL'ni "sirли" qilish (uzun tasodifiy path):**
- Nima qiladi: `/webhook` o'rniga `/webhook/<uzun-tasodif>`. Kuchi: S.
- ❗ **NEGA YETARLI EMAS:** security-by-obscurity — URL SSL shaffoflik

**B) O'RTA — IP allowlist (faqat Telegram IP diapazonidan qabul):**
- Nima qiladi: Telegram'ning e'lon qilingan IP bloklaridan kelgan so'rovlarni
  qabul qiladi. Kuchi: M.
- Nimani hal qilmaydi: shared hosting'da `REMOTE_ADDR` proksi/LiteSpeed
  orqasida noto'g'ri bo'lishi mumkin; Telegram IP diapazoni o'zgaradi (qo'lda
  yangilash kerak); Telegram rasman **secret_token** ni tavsiya qiladi, IP
  emas. Mo'rt.

**C) ILDIZLI — Telegram secret_token (rasmiy mexanizm):**
- Nima qiladi: (1) `.env` ga `WEBHOOK_SECRET` (uzun tasodifiy); (2) `set_webhook`
  da `secret_token=WEBHOOK_SECRET` — Telegram endi har so'rovda
  `X-Telegram-Bot-Api-Secret-Token` sarlavhasini yuboradi; (3) WSGI o'sha
  sarlavhani `hmac.compare_digest` bilan tekshiradi, mos kelmasa **403** va
  `feed_update` umuman chaqirilmaydi. Kuchi: M.
- Nimani hal qilmaydi: `from_user.id` spoofing'ni to'g'ridan-to'g'ri emas,
  lekin uning **yagona yo'lini** (soxta webhook) yopadi — endi update faqat
  Telegram'dan kelishi kafolatlanadi, demak `from_user.id` yana ishonchli
  bo'ladi. S2 (ichki authorization) alohida band bo'lib qolaveradi.

**Tanlov: C.** Bu Telegram'ning rasman tavsiya qilgan mexanizmi, shared
hosting cheklovlariga bog'liq emas, obscurity'ga tayanmaydi.

## K. Tekshiruv rejasi

- **Sinov 1 (soxta so'rov rad etiladi):** deploy'dan keyin sarlavhasiz

- **Regressiya:** webhook `get_webhook_info()` da `url` to'g'ri, `last_error`
