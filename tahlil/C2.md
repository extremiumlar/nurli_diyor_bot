## G. Yechim variantlari

**A) YUZAKI — hozirgi holat (check-then-act guard):**
- Nima qiladi: yozishdan oldin o'qib tekshiradi. Kuchi: S (allaqachon bor).
- ❗ **NEGA YETARLI EMAS:** o'qish↔yozish orasi atomik emas — ikki worker
  oynasida ikkalasi ham "bo'sh" ko'radi; yozma oqimda esa bu himoya umuman
  yo'q. Simptom kamaydi, ildiz joyida.

**B) O'RTA — UNIQUE indeks + ON CONFLICT DO NOTHING:**
- Nima qiladi: DB darajasida `(application_id, question_id)` unique qilinadi,
  `create_answer` konfliktda jim o'tadi. Kuchi: M.
- Nimani hal qilmaydi: eskirgan callback (nomzod eski savol tugmasini
  bosganda) baribir handlergacha keladi; `question_id IS NULL` qatorlar
  qamralmaydi (hozircha bunday yozuv oqimi yo'q, lekin model ruxsat beradi).

**C) ILDIZLI — modelni biznes-qoidaga tenglashtirish (B + idempotent yozuv):**
- Nima qiladi: (1) mavjud dublikatlarni tozalaydigan + partial UNIQUE indeks
  quradigan migratsiya; (2) `create_answer` → `INSERT ... ON CONFLICT DO
  NOTHING` (idempotent — nechta chaqirilsa ham natija bitta); (3) yozma
  oqimga ham xuddi shu himoya avtomatik tatbiq bo'ladi (indeks jadval
  darajasida); (4) `recompute_scores` ga chegara-signal. Kuchi: M.
- Nimani hal qilmaydi: FSM lost-update (C3) va webhook retry (C1) —
  ular alohida bandlar; lekin ularning "dublikat javob" oqibati endi DB
  devoriga urilib yo'q bo'ladi.

**Tanlov: C.** B dan farqi kichik ko'rinadi, lekin C yozma oqimni va kelajak
oqimlarni ham qamraydi hamda modelni qoidaga tenglashtiradi — handler'lar
qanchalik xato qilmasin, DB ikkinchi javobni qabul qilmaydi.

## I. Qadamma-qadam yechim

**Qadam 1 — `migrate_v7.py` (yangi fayl):** dublikatlarni tozalash + indeks.
Xom SQL, idempotent, dialekt-aware:

```python
# 1) Dublikatlarni o'chirish — har (application_id, question_id) uchun
#    eng kichik id (birinchi javob) qoladi:
DELETE FROM application_answers
WHERE question_id IS NOT NULL
  AND id NOT IN (
      SELECT MIN(id) FROM application_answers
      WHERE question_id IS NOT NULL
      GROUP BY application_id, question_id
  );
# 2) Partial unique indeks (SQLite ham, Postgres ham qo'llaydi):
CREATE UNIQUE INDEX IF NOT EXISTS uq_answer_app_question
ON application_answers (application_id, question_id)
WHERE question_id IS NOT NULL;
```

  ga qaytish (git revert); o'chirilgan dublikatlar backup'dan tiklanishi
  mumkin, lekin ular ataylab o'chirilgan — tiklash odatda kerak emas.
